# PhishGuard

PhishGuard is a fully local phishing and scam detection app. Paste an email, SMS, or URL and get back a risk score, verdict, confidence level, detected security signals, highlighted suspicious text, and a plain-English explanation — all running on your own machine with no external API calls.

**How it works:** two CPU-only scikit-learn models (one for URLs, one for email/SMS text) score each submission against hand-crafted security features. Explanations are generated locally from the triggered signals.

---

## Quick start

### 1. Create and activate a virtual environment

```powershell
# Windows — use the Python Launcher to ensure you get the real CPython,
# not the MSYS2 python that may be earlier on PATH
py -3.12 -m venv .venv

# Activate — cmd
.venv\Scripts\activate.bat

# Activate — PowerShell
.venv\Scripts\Activate.ps1

# macOS / Linux
python3 -m venv .venv
source .venv/bin/activate
```

> **Windows note:** if you have MSYS2 installed, `python` on the command line may resolve to `C:\msys64\mingw64\bin\python.exe` instead of the Windows CPython. Always use `py -3.12` (the Python Launcher) to create the venv, and then activate it before running any commands. `run.py` automatically uses the venv Python so activation is not required for that.

### 2. Install dependencies

```bash
pip install -r requirements.txt
```

### 3. Generate the dataset and train both models

```bash
python model/generate_dataset.py
python model/train_model.py
```

This writes six files into `model/`:
`model_url.pkl`, `model_text.pkl`, `feature_order_url.json`, `feature_order_text.json`, `feature_importances_url.json`, `feature_importances_text.json`

Training takes under a minute on any modern CPU.

### 4. Run the app

```bash
python run.py
```

`run.py` starts both the FastAPI backend and the Streamlit frontend in one command, with prefixed log output. Press **Ctrl-C** to stop both.

| Service  | URL                         |
|----------|-----------------------------|
| Frontend | http://localhost:8501        |
| Backend  | http://127.0.0.1:8000       |
| API docs | http://127.0.0.1:8000/docs  |
| Health   | http://127.0.0.1:8000/health|

## Architecture

```
synthetic dataset
  └─ feature extraction (per content_type)
       ├─ URL model  (RandomForest, 7 features)  → model_url.pkl
       └─ TEXT model (RandomForest, 6 features)  → model_text.pkl

FastAPI /analyze  (routes by content_type)
  └─ Streamlit frontend
```

`model/train_model.py` trains a `RandomForestClassifier` and a `StandardScaler + LogisticRegression` pipeline for each model type, selects the higher-F1 one, and saves the winner.

## What changed in v2

The original design trained one model over all 13 features concatenated, but any given row only populated 6–7 of them (URL rows had `0` for every text feature and vice versa). That let the model partly learn "which content type is this" instead of "is this phishing," inflating reported accuracy.

Fixes:

1. **Two models instead of one**, split by content type — matches how the API already branches on `content_type`.
2. **`sender_domain_mismatch` was dead** in v1 training (always `None` inputs → constant `0`). `generate_dataset.py` now emits real `claimed_brand`/`sender_domain` columns so it's a live, learned signal.
3. **Dataset overlap added** — paraphrased phishing samples that don't hit exact keyword lists, and legitimate messages that use urgency-adjacent language for real reasons (appointment reminders, deadlines).
4. **LogisticRegression trained through `StandardScaler`** so the RF-vs-LR comparison isn't biased by unscaled features.
5. **5-fold cross-validation** reported in addition to the single 80/20 split.
6. **No external APIs** — explanations are generated entirely from triggered signals on your machine.

### Honest before/after

| | v1 (single model) | v2 (per-type models) |
|---|---|---|
| Text (email/sms) 5-fold CV F1 | 0.9975 (inflated) | ~0.92 |
| `sender_domain_mismatch` importance | 0.0000 (dead) | ~0.08 (live) |

A lower F1 on the text model is the intended outcome of fixing the dataset — 0.9975 was a sign the task was too easy.

## Known limitations

- Dataset is synthetic. It has been diversified with paraphrases, overlap, and brand/domain mismatches, but won't capture the full variety of real phishing campaigns.
- The URL model reaches ~100% CV F1 because hand-crafted URL rules (suspicious keywords, IP detection) are cleanly separable in a synthetic setup — treat that number with skepticism.
- WHOIS domain-age lookup is disabled during training (`PHISHGUARD_ENABLE_WHOIS=1` to enable) and is best-effort at runtime.
- `requests_sensitive_info` does not handle negation — "no password required" still matches "password".
- This is a demo baseline, not production security software.
